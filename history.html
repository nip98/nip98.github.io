Design Contributions

The PR #469 discussion records the collaborative design process:

  • The u tag convention (vs url) — advocated by Melvin Carvalho based on existing NosDAV implementations
  • Security model — analysis of why NIP-98 does not need a challenge-response (unlike NIP-42), with replay attack mitigation via timestamps
  • Scope boundaries — keeping NIP-98 focused on authentication (401), with payment flows (402) deferred to a separate NIP
  • HTTP status code semantics — distinction between 401 and 403 responses

Related Specifications

  • NIP-96 — HTTP File Storage Integration (uses NIP-98 for auth)
  • NIP-42 — Authentication of clients to relays (challenge-based, distinct from NIP-98)
  • Blossom — blob storage protocol; auth (kind 24242) derived from NIP-98 pattern but server-agnostic (#8)
